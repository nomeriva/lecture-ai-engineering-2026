# 第3回 演習・宿題

## 演習

PythonとPydantic AIを用いた学習支援エージェントを実行し、`--trace`オプションによってツールの呼び出し状況を確認した。

実行した質問は「LoRAとQLoRAの違いは？」とした。

変更前の実行では、`search_glossary`が以下の引数で呼び出された。

- `{"query": "LoRA"}`
- `{"query": "QLoRA"}`

ツール呼び出しは計2回、LLMへのリクエストは2回だった。検索結果を参照したうえで、両技術の違いが説明された。

## 宿題

### 取り組んだレベル

基礎

### 1. 実施内容

`app/agent.py`の`INSTRUCTIONS`を1か所変更し、検索ツールの使用を指示する場合と、検索せずに回答するよう指示する場合を比較した。

変更したのはツール利用に関する指示のみであり、モデルや質問内容は同じ条件とした。

### 2. 比較結果

| 評価項目 | 変更前 | 変更後 |
|---|---|---|
| 使用モデル | gemini-3.5-flash-lite | gemini-3.5-flash-lite |
| 検索ツールの呼び出し | 2回 | 0回 |
| LLMへのリクエスト | 2回 | 1回 |
| 技術的な説明 | おおむね正確 | おおむね正確 |
| 関連情報の特定 | 正確 | 誤りあり |

変更前は`search_glossary`が2回呼び出され、それぞれの用語が検索された。

変更後はツール呼び出しが発生せず、LLMへのリクエストも1回になった。

一般的な技術の説明については大きな差が見られなかったが、変更後の回答では関連する講義回の特定に誤りがあった。

### 3. 考察

今回の実験では、検索を省略するとツール呼び出しとLLMへのリクエストが減少することを確認できた。

一方、LLMの内部知識だけでも一般的な技術の説明は可能だったものの、外部データに依存する情報では不正確な回答が生じた。

この結果から、AIエージェントの設計では、ツールを利用する条件が回答品質と処理効率に影響することが分かった。

ただし、今回の結果は各条件1回ずつの実行に基づくため、応答品質やコストの差を一般化することはできない。

### 4. 気づき・今後の課題

正確性を重視する場合は、外部情報の確認を優先する必要がある。一方、一般的な知識で十分に回答できる場合には、不要なツール呼び出しを省く余地がある。

今後は、質問の種類によって検索の必要性を判断する仕組みを検討したい。また、複数回実行して回答の安定性や処理効率を比較することで、より客観的な評価ができると考えた。
