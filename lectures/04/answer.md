# 第4回 解答

## 演習

学習支援エージェントの回答10件について、根拠・範囲・ヒント・分かりやすさ・回の表示の5項目で評価した。

最初に自分で合否を判定し、その後、LLM-as-a-Judgeを実行して、人間の判定との一致率を確認した。

採点モデルには `gemini-3.5-flash-lite` を使用した。

### 初回の評価結果

| 評価項目 | 一致率 |
|---|---:|
| 根拠 | 7/8（要確認2件） |
| 範囲 | 10/10 |
| ヒント | 10/10 |
| 分かりやすさ | 10/10 |
| 回の表示 | 10/10 |

総合一致率は8/8、自動判定率（coverage）は80%だった。

#05と#08で根拠の判定が保留され、#06では自分とLLMの判定に不一致が生じた。

### 評価基準の改善

`data/eval/rubric.md` の根拠に関する基準を修正した。

用語集に存在しない語について、その旨を明示したうえで一般的な説明をする場合は合格とするルールを追加し、対応する未決定事項を削除した。

修正後、同じ10件を再度採点した。

## 宿題

### 取り組んだレベル

基礎

### 変更内容

評価基準の文言を1つ変更し、LLMによる採点結果への影響を検証した。

変更したのは根拠（grounding）の判定ルールであり、採点モデルや評価対象のデータは変更していない。

### 変更前後の比較結果

| 評価項目 | 変更前 | 変更後 |
|---|---:|---:|
| 根拠 | 7/8 | 9/10 |
| 範囲 | 10/10 | 10/10 |
| ヒント | 10/10 | 10/10 |
| 分かりやすさ | 10/10 | 10/10 |
| 回の表示 | 10/10 | 10/10 |
| 総合一致率 | 8/8 | 10/10 |
| 自動判定率 | 80% | 100% |
| 要確認件数 | 2件 | 0件 |

修正後は要確認件数が2件から0件に減少し、全10件が自動判定の対象となった。

一方で、#08の根拠については人間とLLMの判定が一致せず、判定可能な件数が増えたことと、採点の正確性が高まることは必ずしも同じではないと分かった。

### 考察

今回の実験では、評価基準の曖昧さを解消することで、LLMの判定保留を減らせることが確認できた。

ただし、総合一致率が変更前後とも100%だったのは、自動判定できたケースに限定した集計である。自動判定率と一致率の両方を確認することが重要だと考えた。

また、根拠の評価では変更後も1件の不一致が残ったため、判定基準の明確化だけで完全な評価が実現するわけではない。

### 気づき・今後の課題

LLMによる評価では、単にスコアを見るだけでなく、要確認件数、不一致の内容、判定対象の割合も確認する必要がある。

今後は、評価基準の曖昧さを減らすとともに、人間による確認を組み合わせ、より信頼性の高い評価方法を検討したい。

なお、今回の比較は各条件1回ずつの実行結果であり、結果の再現性については追加検証が必要である。
